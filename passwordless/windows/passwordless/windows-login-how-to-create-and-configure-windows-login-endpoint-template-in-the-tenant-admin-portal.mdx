## Introduction

The **Windows Login Endpoint Template** in the **Tenant Admin Portal** allows Admins to create and manage configuration templates for Windows Login endpoints. It allows defining key settings such as authentication preferences, user access policies, proxy configurations, update schedules, and health alerts.

## Prerequisite

You must have access to the Tenant Admin Portal.

## Steps to create Windows Login Endpoint Template

1. Log in to the **Tenant Admin Portal**.
2. On the homepage, select**Endpoint** from the left menu panel. ![](/images/10501612/69fd1b0cb9e3.png) The **Endpoints** page is displayed.
3. Click **Endpoint Templates** from the top right. ![](/images/10501612/7178b6b03f23.png) The **Endpoint Templates** page is displayed.
4. Click **Create Template**. ![](/images/10501612/be6fc5f731b6.png) The **Create New Template** pop-up box is displayed.
5. Do the following on the pop-up box:Enter **Template Name**.Select **Passwordless** as **Application type** from the dropdown list.Select **Windows Login**as **Endpoint Type** from the dropdown list.Click **Create**. ![](/images/10501612/9aad0995fad3.png) The Windows Login Endpoint Template is created successfully. ![](/images/10501612/ac3c2fa7942d.png)

## Steps to Configure Windows Login Endpoint Template

1. Click the preferred Endpoint template name to configure. ![](/images/10501612/7f486d38861c.png) The Endpoint template details page is displayed. ![](/images/10501612/be75dff47c68.png)
2. Do the following:[Configure Details tab](#h_a6083c2771)[Edit Configure tab](#h_f914d93305)[Configure Windows Alert tab](#h_b04754cbc4)

## Configure Details tab

1. Edit **Template Name** if required.
2. Enter **Template Description**. (Optional)
3. Enter**Name Endpoint As**. (Optional)**Note:** Once the template is selected while pairing an endpoint on the device, the name provided in the **Name Endpoint As** field will be displayed for the endpoint.
4. Select**Time Zone** from the dropdown. (Optional)
5. Click**Save**. ![](/images/10501612/7e806c506a83.png)

### Endpoint Settings

1. Turn on**Enable Only Preferred Machine Login** toggle to allow domain credentials to be used only in preferred machine to log in to windows system.
2. Turn on **Allow any individual with Domain Credentials**toggle to allow individuals to log in to the machine using domain credential.
3. Set **User Cache Validity** duration for which the user data will be saved on the machine as cache.
4. Turn on **Show on-screen Keyboard** toggle to show an on-screen keyboard during logging in for devices which do not have physical keyboard, like tablets.
5. Turn on **Allow Individual Passkey Generation** to allow users to generate individual Windows passkeys for themselves. ![](/images/10501612/004eb2867687.png)
6. Turn on **Allow Shared Passkey Generation** toggle to allow Admins and Supervisors who are passkey owners to generate and assign shared Windows passkeys.
7. Turn on **Allow Bulk - Individual Passkey Generation**toggle to allow admins and supervisors to bulk-generate individual passkeys for the users they manage.
8. Turn on **Allow Bulk - Shared Passkey Generation** to allow admins and supervisors to bulk-generate and assign shared passkeys to users under their management. ![](/images/10501612/b87d1cb39b23.png)
9. Turn on **Override Application Proxy Configuration** toggle to prevent the endpoint from inheriting the application's proxy settings and disable proxy at the endpoint level.Select **Enable Proxy Configuration** option to enable secure network communication through a proxy server.Enter **Proxy URL** in the text field.Enter **Port**in the text field.Enter **Username** in the text field.Enter **Password**in the text field.Click **Save**.

### Auto Update

Select Auto-update from the left menu panel and do one of the following:

1. **Inherited from Application (Default):**This option allows the endpoint to inherit the auto-update configuration defined at the application level.OR
2. **Disable Updates for this endpoint:**This option disables auto-updates for this specific endpoint.OR
3. **Custom Schedule:**This option allows you to configure a dedicated auto-update schedule for a specific endpoint. This option provides control versioning, custom source, and timing independent of the application-level settings.**Note:** This option overrides the default or inherited auto-update behavior for the selected endpoint. ![](/images/10501612/aa5d14a497bd.png)For Custom Schedule do one the following:
4. **Latest Version:**Automatically applies the latest available update version from the default application source.OR
5. **Select Version:**Manually select a specific update version from the available dropdown list.OR
6. **Custom Source:**Allows selection of a custom update source, which may not be available at the application level.**Start Time** _(Required)_**:**Defines when the update window begins. Auto-updates will only be attempted after this time.**End Time** _(Required)_**:** Defines when the update window ends. Auto-updates will stop attempting after this time even if incomplete.**Retry Frequency:**Specifies how many times the system should retry the update within the defined time window if an update attempt fails.**Default:** 5 times**Retry Interval:**Specifies the minimum time interval (in minutes) between retry attempts.**Default:** 30 minutes**Note:**The endpoint will attempt to update only within the defined time window. If an update fails, the retry logic is applied based on the frequency and interval specified.Click **Save**. ![](/images/10501612/ca8ccae1ac7c.png)
