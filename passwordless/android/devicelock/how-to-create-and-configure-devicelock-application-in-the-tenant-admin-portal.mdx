## Introduction

DeviceLock is a secure, passwordless authentication app for Android devices that allows users to authenticate using Facial Recognition, Badge ID, QR Code, NFC ID, or PIN. It enhances security, streamlines user experience, and supports multi-factor authentication in enterprise environments.

## Prerequisite

You must have access to the Tenant Admin Portal.

## Steps to create and configure DeviceLock Application

1. Log in to the**Tenant Admin Portal**. For more details, refer [How to log in to Tenant Admin Portal](/administration/admin-portal/how-to-log-in-to-the-tenant-admin-portal).
2. On the **Applications** page, click **Create Application** in the top right corner. ![](/images/8698213/01825578dc3c.png) The **Create New Application** pop-up box is displayed.
3. Do the following:Enter **Application Name**.Select **Application Type**as **Passwordless**.Click **Next**. ![](/images/8698213/7b427a8d448a.png) The **Select Passwordless Use Case**page is displayed.Select **Device Lock.**Click **Create**. ![](/images/8698213/ab0918644f42.png) The Application is successfully created and listed in the applications list. ![](/images/8698213/8d06a17c6e99.png)
4. Configure the following:[Configure Details tab](#h_ca052cec1f)[Configure Authenticator tab](#h_42bd7c0e76)[Configure Theme tab](#h_159124f871)[Setup Configure tab](#h_b68d169177)[Configure Health Setup tab](#h_be12f7d131)[Configure Connection tab](#h_a9856f4ce1)[Configure Integration tab](#h_012a8cef29)

<Note>
  These are one-time settings, and all the default settings are recommended.
</Note>

## Configure Details tab

Go to **Details**tab and do the following:

1. Update **Application Name**(if required).
2. Add **Description**. (Optional)
3. Set **Time Zone**from the drop-down list. (Optional)
4. Click **Save**. ![](/images/8698213/c1c3f43b42ac.png) The Details tab is successfully configured. ![](/images/8698213/e6d85419e9fb.png)

## Configure Authenticator tab

Go to **Authenticator** tab and do the following:

### Enable username

- **Emp ID/Primary ID:**Enable this option to allow users to authenticate using their Employee ID or Primary ID.(Optional) In the **Custom Label** field, enter a label that appears on the login screen instead of **Emp ID / Primary ID**. ![](/images/8698213/05edfa483795.png)
- **Email:**Enable this option to allow users to authenticate using their Email ID. ![](/images/8698213/7d2eb2bf57ab.png)

### Face

1. Turn on **Face**toggle, to use face as credential.
2. Select the **FR Mode** from the dropdown list to choose the preferred authentication mode.select the preferred face recognition mode:(if required)**Hybrid**: Combines cloud and on-device facial recognition.**Cloud**: Uses cloud-based facial recognition.**On Device**: Uses on-device facial recognition. (if required) ![](/images/8698213/ba4ddb77f367.png)
3. Configure the **Face Match Parameters** and **Liveness Check Parameters**on the Advanced Settings page.**Note**: The parameters are pre-configured. This is done by Oloid admin.
4. Turn on **Strict Error Handing**toggle to ignore the face match error and perform one-to-one face match.**Note:**If a Face Match error occurs, it will be ignored, and a one-to-one facial comparison will still be performed.
5. Turn on **Additional face Match**toggle to perform a one-to-one face match in addition to the regular Face Match.
6. Adjust the slider or enter a value directly into the input box to set the **Face Match Threshold**value. **(for Oloid internal use)****Note:**It defines the required level of similarity between two facial images within the same connection. A higher threshold ensures stricter matching accuracy. ![](/images/8698213/146f62339811.png)
7. Adjust the slider or enter a value directly into the input box to set the **Min. Liveness Probability**. **(for Oloid internal use).****Note:**This is the factor to decide if the image is live or spoofed. The threshold for the image to be considered live is 0.5.
8. Adjust the slider or enter a value directly into the input box to set the **Min. Liveness Quality**. **(for Oloid internal use).****Note:**It defines how "appropriate" the image is for the liveness check. The threshold for good image 0.1. ![](/images/8698213/c711eaa7a94a.png)
9. Click **Save**. ![](/images/8698213/64def45e724c.png) The Face credential is successfully configured. ![](/images/8698213/585932d7049a.png)

### Badge ID

1. Turn on **Badge ID**toggle, to use **Badge ID** as credential.
2. Select a **Badge Type** from the dropdown list (Optional). ![](/images/8698213/a0d9c1152f3e.png)
3. Click **Save**. ![](/images/8698213/e37a756bf6f0.png) The Badge ID credential is successfully configured. ![](/images/8698213/0e79fcd65672.png)

2. Turn on **Show Camera Flip Button** toggle.

### Configure Settings tab

The **Settings** tab is used to configure general endpoint behavior and authentication settings for the application.

1. Click on Settings tab, the settings tab is displayed. ![](/images/8698213/63237e87376c.png)
2. Do the following:Turn on**Enable Offline Mode**toggle to allow endpoint transactions to be processed even when there is no network connectivity.Turn on**Use Group Authorization**toggleto restrict endpoint access to users within the same group associated with the endpoint connected to the application. This ensures that only users in the specified group can authenticate, both online and offline.Turn on **Enable Auto Authentication of Webkey using Local Transaction** toggle to allow user to auto-authenticate the user into Webkey after device login.Turn on **Enable Screen Timeout** toggle to turn off the screen after inactivity. Set **Server Response Ping Timeout**to define how long the Endpoint should wait for a reply from the server before switching to Offline Mode if no response is received. ![](/images/8698213/9e7f6eaa3aab.png) Set **Authentication Timeout** to define how long the system will wait for the user to begin the authentication process before redirecting them back to the first screen.**Note:** The default authentication timeout is **10 seconds**.Set the **Master Admin Override Passcode** to exit the Device Lock app when the device is in Kiosk mode and/or no internet connection is available.Select **Endpoint Template**from dropdown list to apply during the endpoint pairing process.Turn on **Show Clock on Intent/Auth Screens**toggle to display clock on all the Intent, Authentication selection and Identity screens.Click **Save**. ![](/images/8698213/b4194dfef70e.png) ​The **Settings**menu is successfully configured.

### Customize Messages

The Customize Messages tab is used to configure the messages displayed to users on the endpoint during authentication. It allows admin to define action initialization, success, and failure messages, and control how status messages appear after authentication.

1. Click on Customize Messages, the Customize messages screen is displayed. ![](/images/8698213/a62e3d359476.png)
2. Turn on **Enable Action Status Messages**toggle to display the action status of the user's authentication. You can customize the messages your user sees on the DeviceLock app. ![](/images/8698213/474b8a0bb5d4.png)
3. Do the following:Select **Show default messages from the integration** to display the integration's predefined messages. (Optional)Select **Auto-dismiss the error prompt after**and set the preferred time (in seconds).**Note:**The default auto-dismiss time is 5 seconds. ![](/images/8698213/320fccfe582e.png) Enter the **Action Initialization Message** in the text field.Enter **Action Success Message** in the text field.Enter **Action Failure Message** in the text field. ![](/images/8698213/a4c63e5f6249.png) Edit **Authentication Failure Error Message**field (Optional).Click **Save**. ![](/images/8698213/b5039e73433a.png) The **Customize Message**menu is successfully configured.

### Configure Passwordless

The **Configure Passwordless** tab is used to enable and configure passwordless authentication for the application. It allows administrators to select the authentication mode, such as **Device Lock Mode** or **Passwordless Login**, and define related settings such as SSO URL, logout URL, and browser type.

<Frame>
  <img src="/images/8698213/29cbf8a95ffd.png" alt="Screenshot" />
</Frame>

1. Turn on **Enable Passwordless Config**toggle to switch the endpoint's functionality to **Device Lock Mode** or **Passwordless Login**.**Note:**Once enabled, the endpoint will no longer support features like time clocking or review punch data.
2. Do one of the following:**Device Lock Mode:**Select this option to enable Device Lock mode on the endpoint. After successful authentication, the device unlocks and displays the home screen.(Optional) To remove cached browser user data on logout, select **Clear Oloid-Browser cache on logout**.To delete cached user file on logout, select **Delete user folders/cache on logout**.In the **Folder Path** field, enter the folder path to be deleted. ![](/images/8698213/abeb8a71b65c.png) **Passwordless Login:**Select this option to enable Passwordless login on the endpoint. After successful authentication, the user is redirected to the configured URL.![](/images/8698213/01f7f7d09bee.png)

Do one of the following:

1. **Passwordless SSO URL:** Turn on **Passwordless SSO URL** toggle.Enter all the URLs in the **Logout URL** field that should be logged out automatically before a new user logs in.Select the required **Browser or Web-view** **Type** to open the configured URL. ![](/images/8698213/8838552cdf6e.png)
2. **Workday Punch Integration:**Enable **Workday Punch Integration**toggle.Enter the URL to which the Login is enabled for the linked Endpoint.Select the required **Browser or Web-view** **Type** ![](/images/8698213/50efa7901541.png)
3. Set the desired **Timeout** duration (in minutes and seconds) after which the screen automatically times out.
4. Click **Save**. ![](/images/8698213/3c1fcadf90ec.png) The **Configure Passwordless** menu is successfully configured.

## Configure Health Setup tab

Go to **Health Setup**tab and do the following:

1. Enter **Server Name**in the text field.
2. Enter URL in **Add URL that needs to be monitored**in the text field.
3. Click **Add**.**Note:** By default, when you create the application, two servers i.e., **Amazon AWS** and **Platform Portal** are added automatically. ![](/images/8698213/cddf1e167e47.png)

## Configure Connections tab

Connection is a collection of multiple users. Go to **Connection**tab and do the following:

1. Click **+** **Add Connections** to add a connection to the application. ![](/images/8698213/b346403c589b.png) The **Add Connections** pop-up box is displayed.
2. Select connection(s) from the **Select Connection** dropdown list.**Note:** An application can have a maximum of 5 connections.
3. Click **Add**. ![](/images/8698213/8fb278f62926.png) The Connection is successfully added to the application.

## Configure Integrations tab

1. Go to integrations tab and turn on **Enable Integrations to perform cloud-based actions**toggle.
2. Enable the applicable Integration.**Note**: Click **Save**after each action to save your configuration. ![](/images/8698213/248d0066d988.png) The **Integrations**tab is successfully configured. The **DeviceLock**application is configured and listed on the Application page.
